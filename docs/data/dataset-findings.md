# Dataset findings before M1b training (2026-10-24)

Numbers: [dataset-review.md](dataset-review.md) (generated by `make dataset-review`) and
`make train-lengths`. This note says what they mean and what was changed because of them.

## 1. Leakage between training and evaluation databases

Database names alone are not enough: the same public data appears under different names.
Every training database was compared with every evaluation database by the Jaccard
similarity of their table names (`table_overlap`, `tests/test_bird_train.py`).

| training DB | evaluation DB | similarity | what it is | action |
|---|---|---|---|---|
| Spider train `formula_1` (80 q) | Mini-Dev `formula_1` (**bird_diag**) | 1.00 | same Ergast F1 data | excluded in M1b |
| Spider train `soccer_1` (14 q) | Mini-Dev `european_football_2` (**bird_holdout**) | 0.86 | same Kaggle European soccer data | excluded in M1b |
| BIRD train `world` (99 q) | Spider dev `world_1` | 1.00 | same MySQL "world" sample (identical row counts) | excluded |
| BIRD train `airline` (92 q) | Spider dev `flight_2` | 0.50 | same table names, different data | excluded (conservative) |
| Spider train vs Spider test, e.g. `tracking_orders` ~ `e_commerce` (0.88) | | 0.5-0.88 | Spider's own generic look-alike schemas | kept: this is the official split everyone trains on |

**Consequence for M0/M1a:** every Spider-trained adapter so far saw `formula_1` (a
bird_diag database) and `soccer_1` in training. Their bird_diag scores were still at or
below the base model, so the conclusion "the Spider fine-tune does not help on BIRD" holds
(if anything, it was helped by this overlap). M1b removes both.

## 2. Gold SQL health

| set | runs, non-empty | empty result | fails |
|---|---|---|---|
| Spider train | 96.3% | 3.6% | 3 errors |
| Spider dev / test | 95.3% / 97.5% | 4.7% / 2.5% | 0 |
| BIRD train | 92.7% | 3.0% | **402 (4.4%)**: 350 errors, 50 > 100k rows, 2 timeouts |
| bird_diag / bird_holdout | 100% / 99.6% | 0 | holdout: 1 gold > 120 s (scored as gold_error for every model) |

330 of the 402 BIRD train failures come from one database, `retail_world`: it is a cut-down
Northwind, and its questions use tables and columns that are not in the file
(`Order Details`, `Territories`, `EmployeeTerritories`, `Salary`, ...). All 402 are listed in
`data/bird_train/gold_failures.json` and skipped in training. Gold that runs can still be
semantically wrong; published audits found many such errors in BIRD, and this check does not
catch them.

## 3. Training vs evaluation mix

- **BIRD is a different kind of SQL.** BIRD gold queries are about twice as long (median
  162-186 characters vs ~90), use JOIN in ~80% (Spider ~40%), and use CASE/IIF, CAST and
  date functions (10-20%) that Spider never uses. Spider uses GROUP BY and set operations
  more. A Spider-only fine-tune never practises the BIRD constructs, which fits the M1a result.
- **BIRD train matches bird_diag / bird_holdout well** on every feature, a little easier
  (CASE 10% vs 18%, CAST 9% vs 17-20%, dates 4% vs 9-12%).
- **Evidence hints:** 93% of BIRD train questions have one, vs 99-100% in Mini-Dev.
- **Duplicates:** 10 (Spider train) and 11 (BIRD train) repeated (database, question)
  pairs; not worth filtering. Many Spider questions share a gold SQL (paraphrases by design).
- **Database sizes:** BIRD train has fewer, bigger groups (median 117 questions per
  database, max 474 `works_cycles`) than Spider (median 40).

## 4. Record lengths and max_seq_length

| records | p50 | p95 | max (tokens) |
|---|---|---|---|
| Spider, plain | 393 | 1,350 | 2,336 |
| Spider, 3 example rows | 862 | 2,956 | 7,772 |
| BIRD, plain | 669 | 6,627 | 6,803 |
| BIRD, 3 example rows | 1,835 | 23,433 | 23,609 |

The widest BIRD database (`works_cycles`, AdventureWorks, 474 questions) is ~6.7k tokens
without rows and ~23k with rows. A 4096 cap would have dropped it entirely (and five other
wide databases with rows), i.e. the hardest data. M1b uses `max_seq_length: 8192`, and a
record whose rows prompt does not fit falls back to the plain prompt instead of being
dropped, so every database stays in training. Evaluation prompts are smaller (Mini-Dev
databases are narrower; vLLM serves 8192 tokens).

## 5. What M1b trains on

Spider train 7,000 − 94 (formula_1, soccer_1) = 6,906; BIRD train 9,428 − 191 (world,
airline) − 402 (failing gold) = 8,835. About 5% of each source (whole databases) is held out
as validation. Half of the records show 3 example rows per table.
